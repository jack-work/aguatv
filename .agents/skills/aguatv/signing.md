# Runtime receiver signing

`nix build .#apk-signer` provides `bin/aguatv-sign-player` and the Android build-tools 34.0.0 `bin/apksigner` backed by the pinned JDK 17. This is separate from the legacy `aguatv` signing helper. It never creates a key, builds source, uploads, installs or contacts a device.

Invocation: `aguatv-sign-player RELEASE_ID`. IDs match `[a-z0-9][a-z0-9._-]{0,63}`. `--help` and `--version` do not access runtime configuration.

## Configuration and credentials

Default configuration is `/etc/aguatv-signer/config.json`; the unit can set the nonsecret `AGUATV_SIGNER_CONFIG` path. The configuration must be a root-owned regular file not writable by group or other. Nix-managed configuration symlinks are supported.

```json
{
  "inboxDirectory": "/var/lib/aguatv-release/inbox",
  "outputDirectory": "/var/lib/aguatv-release/out",
  "expectedCertificateSha256": "HUMAN_SUPPLIED_64_HEX_PUBLIC_CERTIFICATE_FINGERPRINT",
  "runtimeKeystoreFile": "keystore",
  "storePasswordFile": "store-password",
  "keyPasswordFile": "key-password"
}
```

The credential names are literal basenames resolved only under systemd's `CREDENTIALS_DIRECTORY`. All three must be private regular files, owned by root or the signer. They must have distinct inodes. Alias `home` is fixed. The two password files may contain the same password, but must remain separate runtime files: apksigner consumes successive lines when both flags use the same file.

The human imports the existing keystore and supplies its public certificate fingerprint. No new key or certificate is generated by this program. The service receives no passwords through command arguments or environment variables. Tool errors are reported without relaying subprocess stderr. The apksigner wrapper clears Java option/agent environment hooks and runs the pinned Java executable; the fixed signer launches tools with a fresh minimal environment.

## Approval and staging

A release owner first verifies the source revision and builds `.#player` from approved source. The signer does not run git, nix or repository hooks and cannot itself establish source reachability. Approval is the root-controlled inbox, not a caller-supplied digest.

Stage `<inboxDirectory>/<releaseId>/unsigned.apk` and `receipt.json`:

```json
{
  "schemaVersion": 1,
  "releaseId": "example-1",
  "sourceRevision": "FULL_40_HEX_APPROVED_SOURCE_REVISION",
  "unsignedSha256": "64_HEX_SHA256_OF_STAGED_APK"
}
```

Every inbox path component must be root-owned, not writable by group or other, and not a symlink. Directories 0755 and files 0644 fit that policy. The signer walks paths with directory descriptors and no-follow opens. It copies the APK into its private work directory and checks that exact copy against the receipt before inspecting or signing it. Receipt/config JSON is limited to 16 KiB and APKs to 512 MiB. Each tool call has a 120-second timeout.

Only package `tv.aguatv.player` is accepted. `.#apk` is the older HOME shell and is rejected. Both signed and unsigned package/version metadata must agree.

## Output

The output directory must be private (0700) and owned by the signer. A systemd StateDirectory backing symlink is allowed for this output path; inbox symlinks are not. A private lock serializes invocations, including different template unit instances.

The signer writes `.tmp-<releaseId>/`, signs with v4 disabled, verifies exactly one certificate SHA-256 against the configured pin, fsyncs the completed files and directory, and publishes with Linux `renameat2(RENAME_NOREPLACE)`. An existing release is always an error, even an empty directory. Failed attempts remove only their own work directory; a stale work directory from a killed process requires operator attention.

Published `<outputDirectory>/<releaseId>/` contains exactly:

- `aguatv-player.apk`
- `manifest.json`: `schemaVersion`, `releaseId`, `sourceRevision`, `unsignedSha256`, `signedSha256`, `certSha256`, `package`, `versionCode`, `versionName`, `signedAt` (UTC).

The successful command prints the manifest as one JSON object. Errors go to stderr and return status 1; invalid CLI arguments return 2. No credential paths or values appear in the manifest. The publisher separately copies approved outputs to `apk/aguatv/<releaseId>/`, produces the checksum sidecar and checks the uploaded object against `signedSha256`; it must never overwrite a published release.

## Tests

`nix build .#checks.x86_64-linux.apk-signer` runs the existing Python unittest library against a generated ephemeral test keystore and the built player APK. It does not open production credentials or contact a device. Tests cover real fixture signing, certificate/hash/package rejection, strict approval policy, symlink refusal, distinct credentials, no-replace publication, private StateDirectory backing and removal of ambient Java options from child execution.
